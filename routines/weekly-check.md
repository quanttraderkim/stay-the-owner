# 주간 이해도 점검 / Weekly ownership check

일주일에 한 번(예: 금요일 오후) 실행한다. Run once a week.

## 지시문 / Prompt
지난 7일 동안의 에이전트 기록과 레포 활동만 읽는다(그 이전 기록은 건너뛴다). 그중 중요도가 큰 것(main 병합·배포, 돈이 걸린 결정, 사용자에게 영향 가는 변경, 전략·리서치 결론)을 골라:

1. 깊이 확인하지 않고 넘긴 것으로 보이는 결정 2~4개. 각각 무엇이었는지(링크), 왜 중요한지, 무엇이 확인되지 않았는지, 어디서 봤는지.
2. 그중 하나를 스스로 설명할 수 있는지 묻는 짧은 질문 2~3개. 사람의 전문성에 맞춘다: 개발자는 코드 수준, 개발자가 아니면 "사용자에게 뭐가 달라지나, 문제가 생기면 어떻게 되돌리나, 근거는 뭐였나" 같은 질문.
3. 에이전트 생성량이 사람이 검토할 수 있는 양을 넘었는지 한 줄.
4. 이번 주 에이전트 없이 직접 해볼 것 하나(실제 작업에서, 그 사람이 할 수 있는 것으로 고른다. 예: 직접 플레이해 보기, 사용자 입장에서 확인하기).
5. 읽지 못한 기록이나 레포 목록.

## 위험 신호 / Red flags to look for
- 리뷰 0건 또는 CI 0건으로 main에 병합된 PR
- 병합·배포 직후 몇 시간 안에 들어간 fix 커밋 (테스트가 증명하지 못한 부분이 있었다는 신호)
- 근거가 시뮬레이션이나 에이전트의 자기 평가 하나뿐인 수치 변경
- 대량 삭제(수천 줄)인데 무엇이 지워졌는지 설명이 없는 PR
- 다른 에이전트가 "사용자 지시"라고 주장했지만 확인되지 않은 작업

## 규칙 / Rules
- 사실을 지어내지 않는다. 모르면 모른다고 쓴다.
- 읽기만 한다. 게시, 댓글, 푸시, 메시지 전송을 하지 않는다.
- API 오류로 PR 목록을 못 받으면 커밋 기록으로 대신 보고, 그렇게 했다고 밝힌다.
- 활동이 거의 없으면 한 줄만 보낸다.
